# تقرير تطوير بوت Telegram — حزمة الاحتراف الأساسية

**المشروع:** نجاز كارد  
**النطاق:** تطوير البوت كقناة وصول إضافية للنظام الحالي  
**الهدف:** تقليل أخطاء التكرار، تحسين متابعة الطلبات، إرسال إشعارات قابلة للتنفيذ، وإتاحة الدعم المرتبط بالعملية دون إنشاء نظام مستقل.

## ملخص التنفيذ

تم تطوير طبقة Telegram بحيث تبقى مرتبطة بقاعدة بيانات ومنطق نجاز كارد الحاليين. لم يتم إنشاء محفظة أو جدول طلبات أو نظام إشعارات مالي منفصل للبوت. الطلبات والخصومات وحالات التنفيذ ما زالت تمر عبر المسارات المركزية الموجودة في النظام.

| المجال | ما تم تنفيذه |
|---|---|
| منع إعادة معالجة تحديث Telegram | إضافة حارس `update_id` في نقطة Webhook لمنع معالجة نفس التحديث أكثر من مرة. |
| حماية زر التأكيد | حجز حالة التأكيد ذريًا قبل التنفيذ في الطلب العام وكابينة السداد، مع إعادة المستخدم إلى حالة آمنة عند الخطأ. |
| الإلغاء وانتهاء الحالة | تنظيف حالات المحادثة عند العودة للرئيسية أو الإلغاء، مع الاحتفاظ بإمكانية التحقق من النتيجة من قسم طلباتي. |
| طلباتي | إضافة تفاصيل العملية وسجل الحالة وزر تحديث وربط كل طلب بمعرّفه الرسمي الذي يبدأ بـ `ID`. |
| إشعارات الطلبات | إضافة أزرار «عرض الطلب» و«طلباتي» إلى إشعارات إنشاء الطلب وتغيير حالته. |
| إشعارات الشحن | إضافة أزرار «مدفوعاتي» و«الرئيسية» إلى إشعارات قبول أو رفض شحن الرصيد. |
| الدعم | إضافة مركز دعم من Telegram مرتبط برقم العملية أو باستفسار عام. |
| تكامل الدعم | حفظ محادثات Telegram داخل جداول `chats` و`chat_messages` التي تستخدمها لوحة `admin/chat.php`. |
| الردود التلقائية | إعادة استخدام `chat_auto_replies` وإعداد `chat_welcome` الموجودين في نظام الدعم الحالي. |

## تدفق الدعم الجديد

يبدأ العميل من «المساعدة والدعم» ثم يختار التواصل مع الدعم. يستطيع إرسال رقم العملية الرسمي الذي يبدأ بـ `ID`، أو كتابة «عام» للاستفسار غير المرتبط بطلب. بعد التحقق من ملكية العملية، يرسل العميل رسالته، فتُحفظ في المحادثة المفتوحة الخاصة بالمستخدم مع عنوان يوضح رقم العملية.

تظهر المحادثة مباشرة في لوحة الإدارة الحالية ضمن **المحادثات المباشرة**، مع زيادة عداد الرسائل غير المقروءة للموظفين. وعند رد الموظف من لوحة الإدارة يبقى الرد داخل نفس المحادثة التي أنشأها العميل من Telegram.

## الملفات المعدلة

| الملف | نوع التعديل |
|---|---|
| `includes/telegram_bot.php` | حماية التحديثات والتأكيد، تفاصيل الطلب، أزرار الدعم، حالات الدعم، وحفظ رسائل الدعم في نظام المحادثات الحالي. |
| `includes/notifications.php` | إضافة أزرار Telegram للإشعارات العامة للطلبات وشحن الرصيد مع الحفاظ على التوافق مع الاستدعاءات القديمة. |
| `telegram_integration_complete/telegram_webhook.php` | نقطة دخول Webhook التي تحتوي على حارس التحديثات المكررة. |
| `api/chat.php` | تم تضمينه للمراجعة والتوافق؛ لا يحتاج إلى منطق مستقل للبوت لأن البوت يكتب في نفس جداول المحادثات. |
| `audit/telegram-professional-hardening-audit.md` | ملخص التدقيق السابق لنقاط الدمج والحماية. |

## ملاحظات قاعدة البيانات

تستخدم الوظائف الجديدة الجداول الحالية `chats` و`chat_messages` و`chat_auto_replies`. توجد حماية إنشاء للجداول عند الحاجة، كما تتم مواءمة قيمة `sender_type` لتقبل رسائل النظام التي تستخدمها لوحة المحادثات. يفضل في بيئة الإنتاج إنشاء الجداول وترقية العمود مرة واحدة من خلال لوحة الإدارة أو migration منفصل بدل الاعتماد على إنشاء الجداول أثناء أول رسالة دعم.

لا توجد تغييرات على أرصدة المستخدمين أو أسعار الخدمات أو مزودي الخدمة. كما أن فشل إرسال إشعار Telegram أو فشل حفظ الدعم لا يعيد تنفيذ أي عملية مالية ولا يغير نتيجة الطلب المركزي.

## نتائج فحص الصياغة

تم فحص الملفات التالية باستخدام PHP 8.3، وجميعها اجتازت الفحص دون أخطاء تركيبية:

| الملف | النتيجة |
|---|---|
| `includes/telegram_bot.php` | لا توجد أخطاء صياغة |
| `includes/notifications.php` | لا توجد أخطاء صياغة |
| `telegram_integration_complete/telegram_webhook.php` | لا توجد أخطاء صياغة |
| `api/chat.php` | لا توجد أخطاء صياغة |

## خطوات النشر المقترحة

1. خذ نسخة احتياطية من الملفات الأربعة وقاعدة البيانات قبل الرفع.
2. ارفع الملفات داخل مجلد المشروع مع الحفاظ على المسارات الأصلية.
3. تأكد من أن Webhook يشير إلى ملف `telegram_integration_complete/telegram_webhook.php` الحالي.
4. افتح إعدادات المحادثات وتأكد من أن `chat_enabled` مفعّل إذا أردت استقبال رسائل الدعم.
5. اختبر على حساب تجريبي مرتبط: فتح المساعدة، دعم عام، دعم برقم `ID`، عرض تفاصيل الطلب، الضغط المتكرر على التأكيد، وإلغاء العملية.
6. راقب `admin/chat.php` للتأكد من ظهور رسالة Telegram ضمن المحادثات المفتوحة.

## حالات الاختبار الأساسية بعد الرفع

| الاختبار | النتيجة المتوقعة |
|---|---|
| إرسال نفس تحديث Telegram مرتين | تتم معالجة الأول فقط ولا يتكرر الرد أو الخصم. |
| الضغط مرتين على تأكيد الطلب | يُحجز التنفيذ مرة واحدة فقط. |
| الضغط مرتين على تأكيد كابينة السداد | لا يحدث خصم ثانٍ ولا طلب ثانٍ. |
| البحث عن `ID` يخص مستخدمًا آخر | يرفض البوت ربط الدعم بالعملية. |
| دعم عام | تُنشأ أو تُستخدم محادثة العميل الحالية بعنوان استفسار عام. |
| دعم مرتبط بعملية | يظهر رقم العملية في عنوان المحادثة داخل لوحة الإدارة. |
| رفض شحن الرصيد | تصل رسالة Telegram مع زر «مدفوعاتي». |
| فشل إرسال Telegram | لا يفشل الطلب المركزي ولا يُعاد تنفيذه. |

## حدود الحزمة الحالية

هذه الحزمة لا تضيف نظام تذاكر منفصلًا ولا إرسالًا مباشرًا من Telegram إلى الموظف. الردود تتم من خلال لوحة المحادثات الحالية حتى يبقى السجل موحدًا. كما أن اختبار API الفعلي وWebhook على الاستضافة يجب تنفيذه بعد الرفع باستخدام حساب Telegram تجريبي، لأن ذلك يتطلب اتصال قاعدة البيانات وبيانات Telegram الخاصة ببيئة الإنتاج.
