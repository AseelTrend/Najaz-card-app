# تنظيم Telegram Bot إلى وحدات مستقلة

تم تقسيم منطق بوت Telegram من الملف الأحادي `includes/telegram_bot.php` إلى وحدات وظيفية داخل المجلد `includes/telegram_bot/`، مع إبقاء `includes/telegram_bot.php` كطبقة دخول متوافقة مع جميع الاستدعاءات الحالية.

## المبدأ الأساسي

لا يحتاج `telegram_webhook.php` أو `api/chat.php` أو صفحات الإدارة إلى أي تعديل. جميعها تستمر في تضمين الملف نفسه:

```php
require_once __DIR__ . '/includes/telegram_bot.php';
```

ويقوم الملف القديم بتحميل `includes/telegram_bot/bootstrap.php`، الذي يحمّل الوحدات بالترتيب. أسماء الدوال العامة، معاملات الدوال، الجداول، API، Webhook، إعدادات الموقع، وتدفقات المستخدم الحالية بقيت كما هي.

## طريقة الرفع

ارفع الملف `includes/telegram_bot.php` واستبدل المجلد `includes/telegram_bot/` كاملاً بالمجلد المرفق. يجب الحفاظ على أسماء الملفات والمسارات كما هي. لا ترفع نسخة الاحتياط أو ملفات التطوير الخارجية.

بعد الرفع، نفّذ فحص الصياغة التالي من مجلد المشروع:

```bash
php -l includes/telegram_bot.php
for f in includes/telegram_bot/*.php; do php -l "$f"; done
php -l telegram_webhook.php
php -l api/chat.php
php -l admin/telegram_bot.php
```

## التحقق الوظيفي

يجب اختبار `/start`، عرض الأقسام والخدمات، الطلبات العادية، البحث، تسجيل الدخول والتسجيل، شحن الرصيد، المدفوعات، كبينة السداد، الدعم، الاشتراك الإجباري، Custom Emoji، والأرقام المباشرة. وفي الأرقام المباشرة يجب اختبار شراء رقم جديد، بقاء رقم سابق معلقاً، قائمة الأرقام المعلقة، الاستعادة، فحص الكود، عدم الإلغاء قبل انتهاء المهلة، وحذف رسالة التدفق بعد الاكتمال أو الإلغاء.

تم الحفاظ على نسخة مقارنة محلية أثناء التنفيذ فقط، ولا تدخل ضمن الحزمة النهائية ولا ينبغي رفعها إلى الخادم.

## نتيجة الفحص

تم التحقق من تعريف **161 دالة** في النسخة المنظمة، وهو العدد نفسه الموجود في النسخة الأحادية، كما نجح تحميل ملف الدخول وتعريف الدوال الأساسية دون اتصال بقاعدة البيانات أو تنفيذ عملية Telegram.

لا توجد تغييرات مطلوبة في `api/` أو قاعدة البيانات أو إعدادات Webhook. هذا التعديل تنظيمي داخلي فقط، ولا يغيّر السلوك الوظيفي للبوت.
